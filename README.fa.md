# 🌐 Smart DNS Proxy & Adaptive DNS Engine

**پروکسی DNS هوشمند با قابلیت مسدودسازی تبلیغات، مسیریابی تحریم، کش تطبیقی و موتور انتخاب خودکار سرور بالادست**

---

## 📖 معرفی پروژه

این پروژه یک سامانه **DNS Proxy** ماژولار و بدون وابستگی به کتابخانه‌های خارجی پایتون است که درخواست‌های نام دامنه را دریافت کرده، پس از اعتبارسنجی و نرمال‌سازی، بر اساس اولویت‌های امنیتی و شبکه‌ای تصمیم‌گیری می‌کند و پاسخ را در قالب استاندارد ارائه می‌دهد.

مخزن پروژه در دو نسخه مجزا سازمان‌دهی شده است تا هم قابلیت‌های هسته پایه و هم معماری پیشرفته موتور هوشمند به صورت مستقل قابل اجرا و ارزیابی باشند:

<div dir="ltr" align="left">

```text
Smart_DNS_Proxy_Repo/
├── basic_proxy/                 # نسخه پایه (پروتکل متنی UDP، استعلام واقعی DNS، کش و فیلترینگ)
│   ├── src/                     # dns_proxy.py, upstream_mock.py, config.py, domain_loader.py
│   ├── config.txt               # فایل پیکربندی استاندارد
```

## ⚙️ معماری و ترتیب تصمیم‌گیری

هر درخواست ورودی دقیقاً طبق خط لوله (Pipeline) زیر پردازش می‌شود و نتیجه هر مرحله توسط مراحل بعدی تغییر نمی‌کند:

<div dir="ltr" align="left">

```text
[User Input]
      │
      ├──► exit ──────────────────────────────► Clean Exit (Bye.)
      ├──► Control Commands ──────────────────► stats / cache / reload / engine
      ├──► Invalid Input (spaces, bad chars) ─► NONE | INVALID_INPUT
      │
      ▼  (Normalize: lowercase + strip trailing dot)
      │
      ├──► Match Ad List ─────────────────────► AD_BLOCK  | sinkhole_ip | local_ttl
      ├──► Match Sanction List ───────────────► SANCTION  | proxy_ip    | local_ttl
      ├──► Valid Entry in Cache ──────────────► CACHE     | cached_ip   | remaining_ttl
      │
      ▼  (Query Upstream over UDP)
      │
      ├──► Reply: OK <ip> <ttl> ──────────────► Save to Cache (TTL > 0) ──► UPSTREAM | OK
      ├──► Reply: NOT_FOUND / NXDOMAIN ───────► Do Not Cache ──────────────► UPSTREAM | NOT_FOUND
      └──► Timeout / Network Error ───────────► No Crash ──────────────────► UPSTREAM | SERVER_ERROR
```

</div>

## ✨ قابلیت‌های هسته پایه (`basic_proxy`)

* **اعتبارسنجی و نرمال‌سازی هوشمند دامنه‌ها:** حذف فاصله‌های اضافی، تبدیل به حروف کوچک، حذف نقطه پایانی (`Trailing Dot`) و تطبیق دقیق بر اساس مرز برچسب (`Label-boundary Suffix Match` برای پوشش خودکار زیردامنه‌ها).
* **فیلترینگ چندلایه با اولویت ثابت:**
  1. مسدودسازی دامنه‌های تبلیغاتی (`AD_BLOCK`) با هدایت به `sinkhole_ip` (مانند `0.0.0.0`).
  2. هدایت دامنه‌های تحریم (`SANCTION`) به آدرس سرور واسط (`proxy_ip`).
* **کش محلی مبتنی بر TTL و ظرفیت پویا:** نگهداری رکوردهای معتبر (`OK` با `TTL > 0`)، محاسبه دقیق ثانیه‌های باقی‌مانده، پشتیبانی از سقف ظرفیت (`cache_max_entries`) با سیاست حذف `FIFO` و امکان غیرفعال‌سازی کامل از طریق تنظیمات.
* **پشتیبانی دوگانه از پروتکل ارتباطی UDP:**
  * ارتباط با شبیه‌ساز محلی از طریق پروتکل متنی سبک (`QUERY <domain>`).
  * ساخت و رمزگشایی مستقیم پکت‌های باینری استاندارد DNS (طبق **RFC 1035**) برای استعلام رکورد `A` و `TTL` واقعی از سرورهای عمومی اینترنت (مانند `1.1.1.1` و `8.8.8.8`).
* **مقاومت کامل در برابر خطا (Fault Tolerance):** مدیریت Timeout شبکه، پاسخ‌های نامعتبر و ورودی‌های خالی بدون توقف ناگهانی (`Crash`).
* **دستورهای کنترلی زنده در کنسول و ثبت لاگ:** پشتیبانی از `stats`، `cache`، `reload` و ذخیره ساختاریافته تمام رخدادها در فایل `log.txt`.

## 🧠 قابلیت‌های موتور هوشمند (`smart_dns_engine`)

علاوه بر تمام امکانات نسخه پایه، ماژول‌های زیر برای بهینه‌سازی عملکرد شبکه در شرایط واقعی به سیستم اضافه شده‌اند:

| قابلیت هوشمند | توضیحات فنی |
| ---: | ---: |
| **موتور بنچمارک و تله‌متری SQLite (`dns_engine`)** | ذخیره تاریخچه زمان پاسخ‌دهی سرورهای بالادست در دیتابیس SQLite و محاسبه شاخص‌های آماری `Avg Latency`، `P95 Tail Latency`، `Jitter` و نرخ موفقیت (`Success Rate`). |
| **سیستم امتیازدهی و انتخاب تطبیقی (`AdaptiveSelector`)** | محاسبه امتیاز ترکیبی (۰ تا ۱۰۰) برای هر سرور DNS و تعیین خودکار نقش‌های `PRIMARY` و `BACKUP` بدون دخالت دستی. |
| **Failover آنی و پایش پس‌زمینه (`HealthMonitor`)** | در صورت خطا یا Timeout سرور اصلی، درخواست بلافاصله روی سرور پشتیبان (`BACKUP`) اجرا می‌شود و یک ترد پس‌زمینه سلامت سرورها را به صورت دوره‌ای پایش می‌کند. |
| **همگام‌سازی خودکار لیست تبلیغات آنلاین** | دریافت فهرست‌های به‌روز مسدودسازی تبلیغات از منابع اینترنتی با پشتیبانی از کش محلی و به‌روزرسانی دوره‌ای ۲۴ ساعته در پس‌زمینه. |
| **شبیه‌ساز بار هم‌زمان ۱۰ کاربر (`simulate_users.py`)** | اجرای ۲۵۰ درخواست هم‌زمان از طرف ۱۰ پروفایل کاربری متفاوت (برنامه‌نویس، گیمر، استریمر، کاربر درگیر تبلیغات و ...) با قفل‌گذاری غیرمسدودکننده (`Fine-Grained Locking`). |

## 📊 نتایج بنچمارک و مقایسه عملکرد

نتایج زیر حاصل اجرای آزمون هم‌زمان **۲۵۰ درخواست از ۱۰ پروفایل کاربری** تحت شرایط کاملاً یکسان است:

| شاخص ارزیابی | روتر پایه (`UpstreamRouter`) | موتور هوشمند (`dns_engine`) | میزان بهبود و تحلیل فنی |
| ---: | ---: | ---: | ---: |
| **نرخ پردازش (`Throughput`)** | `148.4 req/sec` | **`156.3 req/sec`** | **+۵.۳٪ افزایش** ظرفیت پاسخ‌دهی در ثانیه |
| **زمان کل اجرای آزمون** | `1.68 sec` | **`1.60 sec`** | **۰.۰۸ ثانیه سریع‌تر** با وجود ثبت زنده در SQLite |
| **میانگین تأخیر اینترنت (`UPSTREAM Avg`)** | `86.568 ms` | **`79.687 ms`** | **~۸٪ کاهش تأخیر** در استعلام‌های خارجی |
| **تأخیر دم توزیع (`UPSTREAM P95`)** | `192.281 ms` | **`165.630 ms`** | **~۱۴٪ کاهش نوسان** و تأخیر در بدترین حالت‌ها |
| **تأخیر پاسخ از کش (`CACHE Avg`)** | `0.016 ms` | **`0.014 ms`** | پاسخ‌دهی در سطح ۱۴ میکروثانیه |
| **تعداد خطاها (`Errors`)** | `0` | **`0`** | پایداری ۱۰۰٪ زیر فشار ترافیک هم‌زمان |

## 🚀 راهنمای نصب و اجرا

### ۱. پیش‌نیازها

* نصب بودن **Python 3.10** یا بالاتر (بدون نیاز به نصب هیچ پکیج خارجی با `pip`).

### ۲. پیکربندی (`config.txt`)

تمام تنظیمات از فایل `config.txt` خوانده می‌شوند:

<div dir="ltr" align="left">

```ini
upstream_ip=127.0.0.1
upstream_port=5354
upstream_timeout_sec=2
sinkhole_ip=0.0.0.0
proxy_ip=192.0.2.10
local_ttl=60
ad_list_file=ad_list.txt
sanction_list_file=sanction_list.txt
cache_enabled=true
cache_max_entries=100
real_dns_enabled=false
```

</div>

### ۳. اجرای نسخه پایه (`basic_proxy`)

ابتدا در یک ترمینال سرور شبیه‌ساز را اجرا کنید:

<div dir="ltr" align="left">

```bash
cd basic_proxy
python src/upstream_mock.py
```

</div>

سپس در ترمینال دوم برنامه اصلی پروکسی را اجرا کنید:

<div dir="ltr" align="left">

```bash
cd basic_proxy
python src/dns_proxy.py
```

</div>

### ۴. اجرای نسخه هوشمند و شبیه‌ساز ۱۰ کاربر (`smart_dns_engine`)

برای اجرای پروکسی هوشمند روی اینترنت واقعی (`real_dns_enabled=true`) و مشاهده جدول امتیازدهی سرورها با دستور `engine`:

<div dir="ltr" align="left">

```bash
cd smart_dns_engine
python src/dns_proxy.py
```

</div>

و برای اجرای آزمون هم‌زمان ۱۰ کاربر و مشاهده گزارش آماری:

<div dir="ltr" align="left">

```bash
cd smart_dns_engine
python simulate_users.py
```

</div>

## 🎮 دستورهای تعاملی داخل کنسول

| دستور | عملکرد |
| ---: | ---: |
| `<domain>` | بررسی و پاسخ‌دهی به نام دامنه در قالب استاندارد ۵ خطی |
| `stats` | نمایش آمار لحظه‌ای تصمیم‌ها (`AD_BLOCK`, `SANCTION`, `CACHE`, `UPSTREAM`, `ERRORS`) |
| `cache` | نمایش رکوردهای معتبر موجود در کش به همراه `TTL` باقی‌مانده |
| `reload` | بارگذاری مجدد فایل‌های فهرست تبلیغات و تحریم بدون نیاز به راه‌اندازی مجدد برنامه |
| `engine` | نمایش جدول زنده امتیازات، نقش‌های `PRIMARY`/`BACKUP` و متریک‌های موتور هوشمند |
| `exit` | توقف ایمن تردهای پس‌زمینه و خروج از برنامه |

</div>
